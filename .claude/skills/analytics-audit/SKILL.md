# Analytics Audit

Audit analytics as a release gate: the app should answer product and monetization questions without collecting identity, raw user content, or high-cardinality data.

## Ground Rules

- Read `AGENTS.md`, `CLAUDE.md`, and repo-local build/test/review skills before auditing.
- Prefer the current diff. If there is no diff, scan the current branch and recent analytics-related commits.
- Never log or quote secrets, API keys, JWTs, `.p8` contents, provisioning profiles, ASC credentials, or raw production config values.
- Do not submit to App Review or mutate App Store Connect.
- Do not add tracking, identity linking, ad identifiers, raw user content, or high-cardinality values.
- Fix only mechanical gaps when `--fix` is present. Report anything involving product policy, data model meaning, purchase behavior, or user consent.

## 1. Map What Exists

Find the analytics layer, initialization path, opt-out storage, and every event call site.

Use targeted searches first:

```sh
rg -n "TelemetryDeck|AnalyticsService|analytics|telemetry|track\\(|signal\\(|send\\(|opt.?out|privacy|NSPrivacy|Product Interaction|Usage Data"
```

Swift/Xcode apps:

- Locate `AnalyticsService.swift`, `TelemetryService.swift`, app entry initialization, settings toggles, `PrivacyInfo.xcprivacy`, `project.yml`, and package dependency wiring.
- Search for `TelemetryDeck.signal`, `.track(`, `.send(`, convenience funnel methods, and any event enum.
- Diff defined events against fired events. Defined-but-never-fired events are a half-wired signal.

React Native/Expo apps:

- Locate `utils/analytics.ts`, `utils/telemetry.ts`, native modules under `modules/`, app config, settings screens, and iOS privacy files generated by prebuild.
- Search for wrapper calls such as `track`, `trackScreen`, `setTelemetryEnabled`, and native bridge calls.
- Confirm native code is guarded for missing modules/app IDs and does not crash in development builds.

Tooling/metadata repos:

- Audit scanners, validators, generated docs, and metadata scripts for analytics/privacy behavior.
- For release-automation tools, keep deterministic validators separate from AI advice and ensure every ASC write path remains dry-run/diff gated.

## 2. Score The Funnel

Assign one tier per app:

- `well-instrumented`: SDK configured, opt-out reachable, core lifecycle/onboarding/core-action/settings funnel present, and monetization funnel present where the product sells anything.
- `half-wired`: SDK and some events exist, but core actions, paywall triggers, purchase outcomes, or settings/opt-out signals are missing.
- `init-only`: SDK initializes and maybe sends launch/session only.
- `silent-by-design`: taxonomy or local logging exists, but transmission is intentionally disabled or debug-only.
- `none-by-design`: no analytics layer because the product explicitly forbids analytics.
- `none`: no analytics layer and no clear product decision explaining why.

Check these groups when the app has the matching surface:

- Lifecycle: launch/session/app foreground.
- Onboarding: started, completed, skipped, permission prompt outcomes.
- Core action: the app's main value event, fired at the model/service source of truth.
- Feature first use: guarded once-per-install or once-per-account, never spammy.
- Paywall: triggered, viewed, dismissed.
- Purchase: started, completed, failed, cancelled, restored.
- Limits: free limit hit, upsell shown.
- Settings: analytics enabled/disabled and key preference changes.

## 3. Privacy Gates

Treat these as hard blockers:

- No names, emails, phone numbers, note text, document titles, addresses, file paths, CloudKit record IDs, exact coordinates, message bodies, or user-entered free text in event names or parameters.
- Parameters are low-cardinality enums, booleans, coarse counts, durations, or buckets. Avoid raw IDs and unbounded strings.
- Analytics is anonymous and opt-out is reachable from Settings, persisted, and honored before sending future events.
- Missing app ID/config no-ops gracefully and does not send development noise to production.
- `NSPrivacyTracking` stays `false`; no IDFA, ad tracking, fingerprinting, or identity stitching is introduced.
- If TelemetryDeck/Product Interaction analytics are active, report the required App Store Connect declaration: Usage Data -> Product Interaction, not linked to identity, not used for tracking, purpose Analytics.
- Privacy manifests stay consistent with the actual SDK/API surface. Do not remove required-reason API entries without proof.

## 4. Fix Policy

With `--fix`, apply only mechanical fixes that match the repo's existing patterns:

- Add a missing import, source entry, package dependency reference, privacy manifest flag, or generated project reference needed for a green build.
- Route an existing toggle to an existing `setTelemetryEnabled`/opt-out API.
- Move an event from a view duplicate to the existing source-of-truth helper when the intended helper already exists.
- Guard missing app IDs, missing native modules, or development builds so analytics no-ops safely.
- Remove or bucket a parameter that clearly leaks raw user content.

Do not auto-fix these:

- A new default-on/default-off policy.
- A new analytics vendor.
- New purchase/paywall instrumentation where product semantics are unclear.
- Data model migrations or CloudKit sync behavior.
- Anything that might drop events needed for compliance or revenue analysis.

## 5. Verification

If code changed, run the narrowest repo-local verification that covers the change:

- Swift/XcodeGen: `xcodegen generate`, then the repo's `/build` and `/test` or documented `xcodebuild` commands.
- React Native/Expo: `npm run typecheck`; also run locale/theme-specific checks when present.
- Swift tooling: `swift build`, `swift test`, and any documented validation command.
- Metadata-only repos: run the metadata validator if present.

If the audit is read-only, report the commands you inspected or skipped and why.
